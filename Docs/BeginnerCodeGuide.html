一、最小 Unity 概念

先把这几个词压到最简单。后面的所有脚本，其实都在重复使用这些动作。

GameObject

场景里的一个物体。玩家、箱子、子弹、喷火器、地面，都可以看成 GameObject。

Transform

每个物体都有的位置、旋转、缩放。移动物体，本质就是改 Transform 的位置。

Update()

每一帧都会执行。需要一直检查输入、一直移动、一直计时，就写在这里。

Collider2D

物体的碰撞范围。没有它，Unity 不知道两个物体有没有碰到。

Trigger

碰到但不挡住。子弹打箱子、玩家捡罐子、火焰烧玩家，都很适合用 Trigger。

Instantiate

生成一个新物体。射击时，就是从子弹 Prefab 生成一颗真正飞出去的子弹。

最小移动例子

把一个物体向右移动，只需要改它的位置。

→

物体移动

必须会：`Time.deltaTime` 可以理解成“这一帧用了多少秒”。乘上它以后，速度就不会因为电脑快慢而忽快忽慢。

三、手臂朝向鼠标

这个脚本读取鼠标位置，把鼠标在屏幕上的位置变成世界里的位置，再让手臂旋转过去。因为 PlayerController 会翻转整个 player，所以这里还要在 player 朝左时修正手臂角度，并使用本地旋转。

挂在瞄准控制物体 旋转 Arm 读取鼠标 翻转武器图片
player └── Arm 旋转中心，armPivot 指向它 └── Armweapon 武器图片 └── ShootPoint 子弹生成点

最小版本先不管鼠标，只让一个物体每帧转一点。

真正项目里多了一步：先算出“鼠标在手臂的哪个方向”，再把方向变成角度。

aimCamera拖 Main Camera把鼠标屏幕坐标换成世界坐标
aimDirection不用手动拖记录当前瞄准方向，方便观察
角度修正不需要拖对象当 player 的 `localScale.x` 小于 0 时，用 `180 - angle` 修正镜像后的手臂旋转，并设置 `localRotation`。

RestorableLadderPlatform.cs

七、被修复后移动的平台

平台被子弹打够次数后变成实体，并在 A、B 两点之间往复移动。玩家站在上面时，平台移动多少，玩家也移动多少。

挂在梯子平台 两点往复 带玩家移动

平台移动的核心只有一行：在 A 点和 B 点之间取一个中间位置。

跟随玩家的核心也很直白：平台这一帧动了多少，就把玩家也加上同样的位移。

Inspector 字段拖什么或填什么说明
pointA可以不拖不拖时，平台原地就是 A 点。
pointB可以不拖不拖时，A 和 B 相同，平台固定不动。
moveDuration填秒数从 A 到 B 需要多久。
hitsToActivate填次数被打几次后激活。

跟随平台没有使用父子关系。这样玩家跳起来时不会被平台继续绑着走，更容易讲清楚。

平台不移动
检查是否打够 `hitsToActivate` 次，或者 `pointA` 和 `pointB` 是否在同一个位置。
玩家站上去一顿一顿
这个脚本已经用 `platformMove` 让玩家跟随。若仍抖动，检查平台 Collider 是否是实体、玩家是否真的站在平台上方。
子弹打不到平台
平台激活前 Collider 是 Trigger，子弹也应有 Trigger 和 Rigidbody2D。

不用手动挂 自创建 暂停游戏

最小 Game Over 只做两件事：显示提示，暂停时间。

十四、如果游戏没反应，先检查什么

最常见配置问题

  • Inspector 里 public 字段有没有拖对象。
  • 需要碰撞的物体有没有 Collider2D。
  • Trigger 事件至少一边有没有 Rigidbody2D。
  • 玩家物体上有没有 `PlayerController`。
  • 地面物体是不是 `Ground` 图层。
  • Prefab 有没有挂对应脚本。

按玩法排查

  • 跳不起来：看 `groundCheck` 和 `groundLayer`。
  • 角色不朝向鼠标：看 `aimCamera`，以及 player 的 Scale 是否正常。
  • 不能射击：看 `canShoot` 是否为 true，或是否拾取黄色罐子。
  • 子弹不打机关：看子弹 Trigger、Rigidbody2D、目标脚本是否同物体。
  • 箱子不停：看地面 Layer 是否是 Ground。
  • 平台不带玩家：看平台是否已激活，并且 Collider 是否变成实体。
  • 喷火器报错：看 `smokeObject` 和 `FireSprite` 是否拖好。
